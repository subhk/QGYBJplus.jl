Physics and operator API

Public operator entry points accept a model so they can use its fields, geometry, coefficients, transform plans, and architecture consistently.

Elliptic inversions

invert_q_to_psi!(model)

QGYBJplus.Elliptic.invert_q_to_psi! — Function
invert_q_to_psi!(S, G; a, workspace=nothing)

Invert spectral QGPV q(kx,ky,z) to obtain streamfunction ψ(kx,ky,z).

Mathematical Problem

For each horizontal wavenumber (kₓ, kᵧ), solve the vertical ODE:

∂/∂z[a(z) ∂ψ/∂z] - kₕ² ψ = q

with Neumann boundary conditions ψ_z = 0 at top and bottom.

Arguments

  • S::ModelFields: ModelFields struct containing q (input) and psi (output)
  • G::RuntimeGeometry: RuntimeGeometry struct with wavenumbers and vertical coordinates
  • a::AbstractVector: Elliptic coefficient aell(z) = f²/N²(z), length nz, sampled at upper cell faces `grid.zfaces[2:end]`
  • workspace: Optional model workspace supplying the Thomas scratch

Implementation Details

The discrete system is tridiagonal with structure:

  • Diagonal: d[k] = -(a[k] + a[k-1]) - kₕ² dz²
  • Upper diagonal: du[k] = a[k]
  • Lower diagonal: dl[k] = a[k-1]

Fortran Correspondence

This matches psi_solver in elliptic.f90.

Mean Mode (kₕ=0) Handling

For the horizontal mean mode (kₓ=kᵧ=0), the equation reduces to: ∂/∂z(a(z) ∂ψ/∂z) = q

With Neumann boundary conditions (∂ψ/∂z=0 at both boundaries), this operator is singular: the homogeneous equation has the constant function as its null space. Consequently:

  1. A solution exists only if ∫q dz = 0 (compatibility condition)
  2. The solution is determined only up to an arbitrary constant

This implementation retains the compatible, vertically varying part of the horizontal-mean PV and fixes the null-space gauge with sum(ψ) = 0. If the depth mean of q is nonzero, that incompatible constant component is projected out (with a warning); no Neumann solution exists for it.

Example

For a model, invert_q_to_psi!(model) uses its own coefficients. With the low-level arguments:

geometry = model.runtime.geometry
a_vec = model.runtime.coefficients.a_ell   # f²/N² at the upper faces
invert_q_to_psi!(model.fields, geometry; a=a_vec)
source
invert_q_to_psi!(model)

Invert the model's potential vorticity q for its balanced streamfunction ψ, in place (model.fields.psi). With WaveMeanFeedback the wave PV qʷ is removed first, so ψ is the flow of q - qʷ. A FixedFlow model has no such inversion: its prescribed ψ is independent of q, and this is an error.

QGYBJplus.Elliptic.invert_B_to_A! — Function
invert_B_to_A!(S, G, a; workspace=nothing)

YBJ+ wave amplitude recovery: solve for A given B = L⁺A.

Mathematical Problem

For each horizontal wavenumber (kₓ, kᵧ), solve:

∂/∂z[a(z) ∂A/∂z] - (kₕ²/4) A = B

with Neumann boundary conditions A_z = 0 at top and bottom.

Arguments

  • S::ModelFields: ModelFields containing B (input), A and C (output)
  • G::RuntimeGeometry: RuntimeGeometry struct
  • a::AbstractVector: Elliptic coefficient aell(z) = f²/N²(z), sampled at upper cell faces `grid.zfaces[2:end]`
  • workspace: Optional model workspace supplying the Thomas scratch

Output Fields

  • S.A: Recovered wave amplitude A
  • S.C: Vertical derivative C = ∂A/∂z (for wave velocity computation)

Mean Mode (kₕ=0) Handling

For the horizontal mean mode (kₓ=kᵧ=0), the equation reduces to: ∂/∂z[a(z) ∂A/∂z] = B

With Neumann boundary conditions (∂A/∂z=0 at both boundaries), this operator is singular: the constant function is in its null space, and only a B with zero depth sum is in its range. The solve therefore:

  1. Projects out the depth mean of B, which no A can produce (the model also removes it from B itself).
  2. Integrates the discrete vertical flux upward from the bottom.
  3. Removes the vertical mean of A, the null-space gauge.

This yields the mean-zero A whose L A is the depth-varying part of B.

Fortran Correspondence

This matches A_solver_ybj_plus in elliptic.f90.

source
invert_B_to_A!(model)

Recover the wave amplitude A, and C = ∂A/∂z, from the envelope B, in place, by the relation of the model's formulation: B = L⁺A for YBJPlus() and PassiveWave(), and the solvability-constrained B = LA for YBJ(), whose recovery also uses the balanced flow's velocity.

QGYBJplus.Elliptic.invert_helmholtz! — Function
invert_helmholtz!(dstk, rhs, G; a, b=zeros, scale_kh2=1.0, bot_bc=nothing, top_bc=nothing, workspace=nothing)

General vertical Helmholtz inversion for each horizontal wavenumber.

Mathematical Problem

Solve the ODE:

a(z) ∂²φ/∂z² + b(z) ∂φ/∂z - scale_kh2 × kₕ² φ = rhs

with Neumann boundary conditions (∂φ/∂z specified at boundaries).

Discretization (matches Fortran helmholtzdouble)

Uses a centered stencil where same a[k], b[k] apply to all diagonals at point k:

  • Bottom (k=1): d = -a[1] - 0.5b[1]Δz - αkₕ²Δz², du = a[1] + 0.5b[1]Δz
  • Interior: d = -2a[k] - αkₕ²Δz², du = a[k] + 0.5b[k]Δz, dl = a[k] - 0.5b[k]Δz
  • Top (k=nz): d = -a[nz] + 0.5b[nz]Δz - αkₕ²Δz², dl = a[nz] - 0.5b[nz]Δz

Boundary flux terms are added to RHS:

  • Bottom: rhs[1] += (a[1] - 0.5b[1]Δz) × Δz × bot_bc
  • Top: rhs[nz] -= (a[nz] + 0.5b[nz]Δz) × Δz × top_bc

Arguments

  • dstk: Output array (nz, nx, ny) for solution φ
  • rhs: Right-hand side array (nz, nx, ny)
  • G::RuntimeGeometry: RuntimeGeometry struct
  • a::AbstractVector: Second derivative coefficient a(z), length nz
  • b::AbstractVector: First derivative coefficient b(z), length nz (default zeros)
  • scale_kh2::Real: Multiplier α for kₕ² term (default 1.0)
  • bot_bc, top_bc: Optional boundary flux arrays (nx, ny) for non-zero Neumann BCs
  • workspace: Optional model workspace supplying the Thomas scratch

Singular columns

Where scale_kh2 × kₕ² = 0 — the horizontal-mean column, and every column when scale_kh2 = 0 — the Neumann problem is singular: constants are in its null space, and a solution exists only for a compatible right-hand side. Such a column is solved with the bottom-row equation replaced by φ[1] = 0 (that row is redundant when the right-hand side is compatible), and its vertical mean is then removed. With nz = 1 a singular column is set to zero, with a warning when its right-hand side is nonzero.

Fortran Correspondence

This matches helmholtzdouble in elliptic.f90 exactly.

QGYBJplus.Operators.compute_velocities! — Function
compute_velocities!(S, G; plans=nothing, f=1, N2=1, compute_w=true, N2_profile=nothing, N2_face_profile=nothing, workspace=nothing, dealias_mask=nothing, pv_forcing=nothing)

Compute the velocity of the balanced flow from the spectral streamfunction ψ̂. As in Xie & Vanneste (2015) and Wagner & Young (2016, eq. 3.22), ψ is the streamfunction of the Lagrangian-mean flow, so these are Lagrangian-mean velocities. Wave orbital velocities and the Stokes drift that relates the Lagrangian to the Eulerian mean are added by compute_wave_velocities!.

Physical Equations

Horizontal velocities from geostrophic balance:

u = -∂ψ/∂y  →  û(k) = -i kᵧ ψ̂(k)
v =  ∂ψ/∂x  →  v̂(k) =  i kₓ ψ̂(k)

Vertical velocity from the QG omega equation (see compute_vertical_velocity!):

N² ∇²w + f² ∂²w/∂z² = 2f [J(ψ_z, ∇²ψ) - J(ψ_x, ψ_xz) - J(ψ_y, ψ_yz)] + f ∂z(D_t qʷ)

where the last term, from wave feedback, is supplied through pv_forcing. w is computed on the faces between levels and stored at cell centres.

Algorithm

  1. Compute û = -i kᵧ ψ̂ and v̂ = i kₓ ψ̂ in spectral space
  2. Transform to physical space via inverse FFT
  3. Optionally solve omega equation or use YBJ formula for w

Arguments

  • S::ModelFields: ModelFields with ψ (input) and u, v, w (output)
  • G::RuntimeGeometry: RuntimeGeometry with wavenumbers kx, ky
  • plans: FFT plans (auto-generated if nothing)
  • f, N2: Scalar Coriolis frequency and fallback buoyancy frequency squared
  • compute_w::Bool: If true, compute vertical velocity; otherwise w is zeroed
  • N2_profile::Vector: Optional cell-center N²(z) profile, the fallback when no face profile is given
  • N2_face_profile::Vector: Optional upper-face N²(z) profile, used by the vertical velocity (w lives on the faces)
  • workspace: Optional model workspace for scratch buffers
  • dealias_mask: Optional 2D dealiasing mask for omega equation RHS (quadratic term). Should be the same mask used for other nonlinear terms (typically 2/3 rule).
  • pv_forcing: Optional function that writes the wave-PV forcing D_t qʷ into a spectral buffer (see compute_vertical_velocity!)

Returns

Modified ModelFields with updated u, v, w fields.

Note

For the instantaneous (Eulerian) velocity including the waves, use compute_total_velocities!.

Fortran Correspondence

Matches compute_velo in derivatives.f90.

Uses the model's own coefficients, stratification profile, and dealiasing.

QGYBJplus.Operators.compute_vertical_velocity! — Function
compute_vertical_velocity!(S, G, plans; f=1, N2=1, N2_profile=nothing, N2_face_profile=nothing, workspace=nothing, dealias_mask=nothing)

Solve the QG omega equation for ageostrophic vertical velocity.

Physical Background

In quasi-geostrophic dynamics, the leading-order horizontal flow is non-divergent (∇·u_g = 0). Vertical motion arises from ageostrophic corrections that maintain thermal wind balance as the flow evolves. Eliminating the time derivatives between the vorticity and buoyancy equations,

ζ_t + J(ψ, ζ) = f w_z,        b_t + J(ψ, b) + N² w = 0,        b = f ψ_z,

gives the omega equation

N² ∇²w + f² ∂²w/∂z² = 2∇·Q = 2f [J(ψ_z, ∇²ψ) - J(ψ_x, ψ_xz) - J(ψ_y, ψ_yz)]

The first forcing term is differential vorticity advection by the thermal wind; the other two are the deformation part of the Q-vector forcing.

Numerical Method

  1. Compute the forcing on the faces between levels with omega_eqn_rhs!
  2. For each horizontal wavenumber (kₓ, kᵧ), solve the tridiagonal system for w on the interior faces with the Thomas algorithm (O(nz) per wavenumber; the system is strictly diagonally dominant for kₕ > 0, so no pivoting is needed). N² is sampled on the faces.
  3. Average the two faces of each cell to store w at cell centres, and transform to physical space

The discrete forcing and stencil are those implied by the model's flux-form PV inversion, so w satisfies the model's discrete vorticity and buoyancy equations exactly. A LinearDynamics() model does not advect its flow, but its w is still that of the full QG equations: the vertical motion that the flow's own advection drives.

Boundary Conditions

w = 0 at z = -Lz and z = 0 (rigid lid and bottom).

Arguments

  • S::ModelFields: ModelFields with ψ (input) and w (output, cell centres)
  • G::RuntimeGeometry: RuntimeGeometry structure
  • plans: FFT plans
  • f, N2: Scalar Coriolis frequency and fallback buoyancy frequency squared
  • N2_profile::Vector: Optional cell-centre N²(z), used only when N2_face_profile is not given (default: constant N² = N2)
  • N2_face_profile::Vector: Optional N²(z) on the upper face of each level, where the omega equation is solved
  • workspace: Optional model workspace for scratch buffers
  • pv_forcing: Optional function pv_forcing(D) that writes the material derivative of the wave PV following the mean flow, D = ∂ₜqʷ + J(ψ, qʷ), into the spectral array D at the levels. With wave feedback the PV equation D_t (q_g + qʷ) = 0 adds -D_t qʷ to the vorticity equation, so the omega equation gains the forcing f ∂z(D_t qʷ).
  • dealias_mask: 2D dealiasing mask for omega equation RHS. If nothing (default), the standard radial 2/3 rule is used to avoid aliasing in the quadratic Jacobian term.

Fortran Correspondence

Follows the omega-equation solver of the Fortran implementation, with the full Q-vector forcing and w on the faces.

QGYBJplus.Operators.compute_ybj_vertical_velocity! — Function
compute_ybj_vertical_velocity!(S, G, plans; f=1, N2=1, N2_profile=nothing, N2_face_profile=nothing, workspace=nothing, skip_inversion=false, t=nothing)

Compute vertical velocity from near-inertial wave envelope using YBJ+ formulation.

Physical Background

Near-inertial waves induce vertical motion through the modulation of their envelope. Following Asselin & Young (2019) equation (2.10):

w₀ = -(f²/N²) A_{zs} e^{-ift} + c.c.

where:

  • A is the true wave amplitude (recovered from evolved B via L⁺A = B)
  • A{zs} = ∂s(Az) = (1/2)(∂x - i∂y)(Az) is the complex horizontal derivative
  • The complex derivative uses s = x + iy, so ∂s = (1/2)(∂x - i∂_y)
  • c.c. denotes complex conjugate

Expanding this gives:

w = -(f²/N²) * [cos(ft)·(Re(∂A_z/∂x) + Im(∂A_z/∂y)) + sin(ft)·(Im(∂A_z/∂x) - Re(∂A_z/∂y))]

Az and N² are evaluated on the faces between levels, so the face values of w satisfy discrete continuity, `wz = -(ux + vy), exactly for the wave velocityu + iv = e^{-ift} LA`; A_z = 0 makes w vanish on the bottom and top faces. The face values are averaged to cell centres for storage.

Physical Interpretation

This represents vertical motion induced by:

  • Horizontal gradients in the wave envelope's vertical structure
  • Wave packet propagation and refraction
  • Strong w occurs where wave amplitude varies both horizontally and vertically
  • The velocity oscillates at inertial frequency f

Algorithm

  1. A Recovery: Solve L⁺A = B using invertBto_A!

    • L⁺ is the YBJ+ elliptic operator
    • Tridiagonal solver in z for each horizontal wavenumber

  2. Vertical Derivative: Compute A_z = ∂A/∂z

    • Uses second-order finite differences

  3. Horizontal Gradients: Compute ∂(Az)/∂x, ∂(Az)/∂y

    • Spectral differentiation: multiply by i kₓ, i kᵧ

  4. Combine: Apply equation (2.10) with oscillating e^{-ift} factor

Arguments

  • S::ModelFields: ModelFields with B (input) and w (output)
  • G::RuntimeGeometry: RuntimeGeometry structure
  • plans: FFT plans
  • f, N2: Scalar Coriolis frequency and fallback buoyancy frequency squared
  • N2_profile::Vector: Optional cell-centre N²(z), used only when N2_face_profile is not given (default: constant N² = N2)
  • N2_face_profile::Vector: Optional N²(z) on the upper face of each level, used to recover A from B and in the factor f²/N² of w
  • workspace: Optional model workspace for scratch buffers
  • skip_inversion::Bool: If true, skip B→A re-inversion and use existing S.A, S.C. Use this when A/C were already computed in the timestep with the correct stratification. Default: false (re-inverts for safety).
  • t::Real: Current time for computing the oscillating velocity e^{-ift}. If not provided (default), computes only the cosine component (t=0 snapshot).

Fortran Correspondence

Matches YBJ vertical velocity computation in the Fortran implementation.

Important Note

When skip_inversion=false (default), this function re-inverts B→A using the provided N2faceprofile (or the legacy N2_profile/constant fallback). If the timestep computed A/C with a different stratification, this will give inconsistent results. For runs with nonuniform N², either:

  1. Pass skip_inversion=true and ensure A/C are already computed correctly
  2. Pass the exact same N2_face_profile that was used in the timestep

References

  • Asselin & Young (2019), J. Fluid Mech. 876, 428-448, equation (2.10)

QGYBJplus.Operators.compute_total_velocities! — Function
compute_total_velocities!(S, G; t, plans=nothing, f=1, N2=1, compute_w=true, N2_profile=nothing, N2_face_profile=nothing, workspace=nothing, dealias_mask=nothing, include_wave_velocity=true, formulation=YBJPlus(), pv_forcing=nothing)

Instantaneous (Eulerian) velocity at time t: the velocity a fluid particle at a fixed point sees, including the near-inertial oscillation.

Physical Background

The QG streamfunction ψ is that of the Lagrangian-mean flow (Xie & Vanneste 2015; Wagner & Young 2016, eq. 3.22: ū + U^S = ∇⊥ψ). The Eulerian-mean velocity is therefore the Lagrangian mean minus the Stokes drift, and the waves add their orbital velocity u + iv = e^{-ift} LA (Asselin & Young 2019, eq. 1.2) and vertical velocity:

u + iv = (u^L + iv^L) - (u^S + iv^S) + e^{-ift} LA
w      = w^L - w^S + [-(f²/N²) A_{zs} e^{-ift} + c.c.]

compute_velocities! gives the Lagrangian mean (u^L, v^L, w^L), and compute_wave_velocities! the rest.

Trajectories integrated with this velocity resolve the inertial oscillation, so their time step must be small compared with 1/f; their drift averaged over an inertial period is the Lagrangian mean. For phase-averaged trajectories use the Lagrangian-mean velocity of compute_velocities! instead.

Arguments

  • S::ModelFields: ModelFields with ψ, A, B, C (input) and u, v, w (output)
  • G::RuntimeGeometry: RuntimeGeometry structure
  • t: Time for the inertial phase e^{-ift} (required)
  • plans: FFT plans
  • f, N2: Scalar Coriolis frequency and fallback buoyancy frequency squared
  • compute_w::Bool: If true, compute the vertical velocity
  • N2_profile, N2_face_profile: Optional cell-centre and upper-face N²(z)
  • workspace: Optional model workspace for scratch buffers
  • dealias_mask: Optional 2D dealiasing mask for the omega equation
  • include_wave_velocity::Bool: If false, omit the orbital velocity, leaving the Eulerian-mean velocity
  • formulation: YBJPlus() (default) or YBJ(), which fixes how LA follows from B
  • pv_forcing: Wave-PV forcing of the mean-flow w in coupled runs (see compute_vertical_velocity!)

QGYBJplus.Operators.compute_wave_velocities! — Function
compute_wave_velocities!(S, G; t, plans=nothing, f=1, N2=1, compute_w=true, include_wave_velocity=true, N2_profile=nothing, N2_face_profile=nothing, formulation=YBJPlus(), workspace=nothing)

Add the wave part of the instantaneous velocity at time t to the Lagrangian-mean velocity in S (from compute_velocities!): subtract the Stokes drift, which turns the Lagrangian mean into the Eulerian mean, and add the wave orbital velocity.

Physical Background

  1. Wave velocity (Asselin & Young 2019, eq. 1.2): u + iv = e^{-ift} LA, with L = ∂_z (f²/N²) ∂_z, and the vertical velocity w = -(f²/N²) A_{zs} e^{-ift} + c.c. (eq. 2.10). For YBJPlus(), B = L⁺A, so LA = B + (kₕ²/4)A in spectral space; for YBJ(), B = LA.

  2. Stokes drift (Wagner & Young 2016, eqs. 3.16-3.20). With the buoyancy action M = (f²/N²) A_z, so that M_z = LA, and ∂_s = (∂ₓ - i∂ᵧ)/2:

    J₀ = M_z* ∂_{s*}M_z - (∂_{s*}M*) M_zz,     i f U^S = J₀,
K₀ = M_z* M_{ss*} - (∂_{s*}M*) M_{sz},     i f w^S = K₀* - K₀,

    that is u^S = Im(J₀)/f, v^S = -Re(J₀)/f, w^S = -2 Im(K₀)/f, where M_{ss*} = Δ_H M / 4. The drift (u^S, v^S, w^S) is non-divergent. As ψ is the Lagrangian-mean streamfunction (their eqs. 3.22-3.23), the Eulerian mean is the Lagrangian mean minus this drift.

Discretization

M lives on the faces between levels, with A_z (S.C) and N² there; it vanishes on the bottom and top faces. M_z = LA and M_{sz} = ∂_s LA are then exact at the cell centres, by the flux form of L, so no derivative of the stratification is needed. The second term of J₀ is formed on the faces, where M and M_zz = δ_z LA both live, and averaged onto the centres; in K₀, M is averaged onto the centres. Every term is therefore centred at the level it is added to, and the drift converges at second order in Δz.

Arguments

  • S::ModelFields: ModelFields with A, B, C (input) and u, v, w modified (output)
  • G::RuntimeGeometry: RuntimeGeometry structure
  • t: Time for the inertial phase e^{-ift}; required with include_wave_velocity
  • plans: FFT plans
  • f, N2: Coriolis frequency and fallback buoyancy frequency squared
  • compute_w::Bool: If true (default), also correct the vertical velocity
  • include_wave_velocity::Bool: If false, only subtract the Stokes drift, which leaves the Eulerian-mean velocity
  • N2_profile::Vector: Optional cell-centre N²(z), used only when N2_face_profile is not given
  • N2_face_profile::Vector: Optional N²(z) on the upper face of each level, where M = (f²/N²) A_z is formed
  • formulation: YBJPlus() (default) or YBJ(), which fixes how LA follows from B
  • workspace: Optional model workspace for scratch buffers

References

  • Asselin & Young (2019), J. Fluid Mech. 876, 428-448, equations (1.2), (2.10)
  • Wagner & Young (2016), J. Fluid Mech. 802, 806-837, equations (3.16)-(3.23)
  • Xie & Vanneste (2015), J. Fluid Mech. 774, 143-169

The domain-mean kinetic energy of the balanced flow, ½⟨u² + v²⟩ (m² s⁻² in a dimensional setup): the mean_flow_KE that the energy diagnostics record. It is computed from the prognostic q (or a FixedFlow model's prescribed ψ), changes no model field, and is a host scalar, also on a GPU.

source
flow_kinetic_energy(u, v) -> KE

Compute domain-integrated kinetic energy of the geostrophic flow (simple version).

Physical Background

The kinetic energy of the balanced flow:

KE = (1/2) ∫∫∫ (u² + v²) dx dy dz

This is a key diagnostic for:

  • Model stability (unbounded growth indicates numerical issues)
  • Energy conservation/dissipation rate
  • Turbulent cascade analysis

Returns

Total kinetic energy (domain sum, not mean) in nondimensional units.

Note

  • This is NOT normalized by volume. For energy density, divide by nx×ny×nz.
  • For complex arrays only the real part contributes.
  • For energy with spectral dealiasing, use flow_kinetic_energy_spectral instead.

QGYBJplus.Diagnostics.wave_energy — Function
wave_energy(model) -> (; kinetic, potential, correction)

The domain-mean wave energies of model, as the energy diagnostics record them (wave_KE, wave_PE, and wave_CE): the kinetic energy ½⟨|LA|²⟩ of the wave velocity, the potential energy, and the YBJ⁺ correction (zero for YBJ()). With the balanced flow's energy, the potential and correction energies make up the energy that the ideal coupled system conserves (Asselin & Young 2019, eq. 3.7); the kinetic energy is informational. They are rebuilt from the prognostic B and change no model field.

source
wave_energy(B, A) -> (E_B, E_A)

Compute domain-integrated wave energy from both B and A fields (simple version).

Physical Background

Two measures of wave energy in the model:

  1. Envelope energy E_B = Σ |B|²

    • Based on the evolved wave envelope
    • Directly available from prognostic variable

  2. Amplitude energy E_A = Σ |A|²

    • Based on the recovered wave amplitude
    • More physically meaningful for wave energy flux

Use Cases

  • Monitor total wave energy conservation/dissipation
  • Compare EB and EA to verify B→A recovery
  • Track energy exchange with mean flow

Arguments

  • B::Array{Complex,3}: Wave envelope (spectral or physical)
  • A::Array{Complex,3}: Wave amplitude (spectral or physical)

Returns

Tuple (EB, EA) of domain-summed squared magnitudes.

Note

These are domain SUMS, not means. For energy density, divide by grid volume.

Compute a(z) = f² / N²(z), with N² bounded below by √eps times its largest value. The bound is relative so that it means the same in every unit system: an absolute √eps ≈ 1.5e-8 would clamp realistic abyssal N² in s⁻².

QGYBJplus.is_dealiased — Function
is_dealiased(i, j, nx, ny)

Test whether the Fourier mode with indices (i, j) (FFTW order) lies inside the two-thirds cutoff: the ellipse (iₓ/Kₓ)² + (i_y/K_y)² ≤ 1 in mode index, with Kₓ = ⌊nₓ/3⌋ and K_y = ⌊n_y/3⌋, which is a disk on a square grid. When nₓ or n_y is divisible by three, the boundary itself is excluded (< 1), so that no product of two retained modes aliases onto a retained one.

QGYBJplus.compute_hyperdiff_coeff — Function
compute_hyperdiff_coeff(; dx, dy, dt, order=4, efold_steps=10, kmax_fraction=2/3)

Coefficient ν of a hyperdiffusion term ν kₕ^order that damps the target wavenumber kmax_fraction π / min(dx, dy) by one e-fold every efold_steps steps of length dt.

The default, kmax_fraction = 2/3, targets the largest wavenumber the two-thirds dealiasing keeps. kmax_fraction = 1 targets the Nyquist wavenumber instead; nonlinear runs remove it, so the smallest scale they keep is then damped (3/2)^order times more weakly than intended.

QGYBJplus.dimensional_hyperdiff_params — Function
dimensional_hyperdiff_params(; nx, ny, Lx, Ly, dt, order=4, efold_steps=10, kmax_fraction=2/3)

The coefficient of compute_hyperdiff_params for both the flow and the waves, as a named tuple in the naming of the original Fortran model: νₕ₁ and νₕ₁ʷ (the coefficients), ilap1 and ilap1w (the Laplacian powers, order ÷ 2), an unused second operator (νₕ₂ = νₕ₂ʷ = 0, ilap2 = ilap2w = 2), order, and efold_steps. To configure a model, pass the coefficient to the closure:

ν = dimensional_hyperdiff_params(; nx, ny, Lx, Ly, dt).νₕ₁
closure = HorizontalHyperdiffusivity(
    flow=FlowHyperdiffusivity(coefficient=ν, order=4),
    wave=WaveHyperdiffusivity(coefficient=ν, order=4))
