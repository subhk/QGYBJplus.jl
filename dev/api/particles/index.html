Particle API

Particles are optional model-owned data. Initialize them after model construction:

QGYBJplus.UnifiedParticleAdvection.ParticleConfig — Type
ParticleConfig{T}(; x_min=0, x_max, y_min=0, y_max, z_level, kwargs...)

Configure a regular horizontal particle grid at z_level, with positions stored in precision T. nx_particles and ny_particles default to 10. Particles move with the horizontal velocity and keep their depth.

particle_advec_time delays the release until the simulation time reaches it; once released, particles keep moving in later runs. It and save_interval are times, kept in Float64 whatever T is.

integration_method selects the trajectory integrator: :euler, :rk2 (default), or :rk4. Each integration stage interpolates the velocity linearly in time between the start and the end of the particle step, so in an evolving flow :rk2 and :rk4 are second-order accurate in time and :euler first-order. :rk4 is still more accurate per step where trajectories curve strongly.

interpolation_method selects the spatial interpolation: TRILINEAR (O(h²)), TRICUBIC (default; Catmull-Rom, O(h³)), or QUINTIC (degree-5 Lagrange, O(h⁶)). ADAPTIVE is deprecated and now uses TRICUBIC.

A finite save_interval makes the tracker keep an in-memory history of the positions, up to max_save_points records, for write_particle_trajectories: when a run starts and then at the multiples of save_interval (every step for 0). The default, Inf, keeps none: simulations write trajectories with a ParticleOutputManager.

wave_motion selects how particles feel the near-inertial waves:

  • :averaged (default): phase-averaged trajectories, advected by the Lagrangian-mean velocity of the balanced flow, ∇⊥ψ. As ψ is the Lagrangian-mean streamfunction (Xie & Vanneste 2015; Wagner & Young 2016), this already contains the waves' Stokes drift.
  • :instantaneous: trajectories that follow the inertial oscillation, advected by the wave velocity e^{-ift} LA, with the phase evaluated at each integration stage, plus the Lagrangian mean minus the Stokes drift of horizontal orbits. The orbits make up that part of the drift themselves, so over an inertial period the particles drift with the Lagrangian mean, as with :averaged; the part of the Stokes drift from vertical excursions, which particles that keep their depth do not make, stays in the mean. The particle time step must resolve the inertial period (f Δt ≲ 0.2).

use_ybj_w and use_3d_advection were removed and must stay false.

QGYBJplus.UnifiedParticleAdvection.ParticleTracker — Type

Particle tracker: configuration, particle state, and the velocity that advects the particles, on the model's architecture.

source
QGYBJplus.UnifiedParticleAdvection.ParticleState — Type

Particle state: positions, global IDs, and the horizontal velocity at the particles' time, with the in-memory trajectory history. Positions and velocities live on the model's architecture (copy them with Array to index them on the host when the model runs on a GPU); the IDs and the history are host arrays.

Positions and velocities have the particles' precision T, but times are Float64: in single precision, times of a few months are already rounded to seconds, which would distort the time interpolation of the velocity.

QGYBJplus.UnifiedParticleAdvection.initialize_particles! — Function
initialize_particles!(model, config)
initialize_particles!(simulation, config)

Install particles on model (or on the simulation's model), placed by config: a ParticleConfig or ParticleConfig3D, usually from a helper such as particles_in_box. They replace any particles the model had, and are advanced by run! with the model's own coefficients; read them from model.particles. Particles installed through a simulation start at its clock's time, which is the restart time after restore!.

source
initialize_particles!(tracker, config)

Place the particles of config (a ParticleConfig or ParticleConfig3D) on tracker, which adopts the configuration. Particles from an earlier initialization are replaced, with their history, release, and velocity. Every particle must lie within the grid's vertical extent: z is a coordinate, negative below a lid at z = 0, not a depth.

source
QGYBJplus.UnifiedParticleAdvection.advect_particles! — Function
advect_particles!(model, Δt; current_time=nothing)

Advance the particles installed on model from current_time (default: the particles' own time) to current_time + Δt. The model's state is taken as the velocity at the end of that interval, so call this after advancing the model over the same interval, as run! does. The velocity at the start is the one kept from the previous call that ended at current_time; integration stages interpolate linearly in time between the two. Without it (on the first call, or after a gap) the end-of-interval velocity is used for the whole step.

source
advect_particles!(tracker, state, grid, dt, current_time=nothing; f, N2, N2_profile, N2_face_profile, formulation, workspace)

Advance the particles from current_time (default: the particles' own time) to current_time + dt. state is taken as the fluid state at the end of that interval, so call this after advancing the model over it, as run! does. The velocity at the start of the interval is the one kept from the previous call, if that call ended at current_time; integration stages interpolate linearly in time between the two. Without it (on the first call, or after a gap), the end-of-interval velocity is used for the whole step.

Particles stay in place until the simulation time reaches particle_advec_time, and keep moving once released.

Keywords

The velocity diagnostic's coefficients default to those of the model that owns the tracker (a tracker built with ParticleTracker(config, model) or initialize_particles!(model, config)); for a tracker without a model they default to f = 1, N2 = 1, and YBJPlus().

  • f, N2: Physical coefficients used by the velocity diagnostic.
  • N2_profile: Optional cell-center N²(z) profile for nonuniform stratification.
  • N2_face_profile: Optional upper-face N²(z) profile, used by the Stokes drift of :instantaneous trajectories.
  • formulation: YBJPlus() or YBJ(), which fixes how the wave velocity LA follows from B.
  • workspace: Optional model workspace for the velocity diagnostic's scratch.

See ParticleConfig for the two trajectory models, wave_motion = :averaged (default) and :instantaneous.

source
QGYBJplus.UnifiedParticleAdvection.interpolate_velocity_at_position — Function
interpolate_velocity_at_position(x, y, z, tracker, t=tracker.particles.time)

The horizontal velocity (u, v) that advects a particle at (x, y, z) at time t, with the configured interpolation. Within the current particle step the velocity is interpolated linearly in time between its start and its end. With wave_motion = :instantaneous the wave velocity is added at the inertial phase of t. The tracker must hold a velocity, recorded by a run or by advect_particles!.

source
configuration = ParticleConfig{Float64}(
    x_min=first(model.grid.x_faces),
    x_max=last(model.grid.x_faces),
    y_min=first(model.grid.y_faces),
    y_max=last(model.grid.y_faces),
    z_level=-100.0,
    nx_particles=16,
    ny_particles=16,
    interpolation_method=TRILINEAR,
)
initialize_particles!(model, configuration)

run!(simulation) advances installed particles after each model step. A manual update takes the model's current state as the velocity at the end of the particle step, so advance the model over the same interval first:

step!(model, timestepper)
advect_particles!(model, timestepper.Δt; current_time=t)

QGYBJplus.UnifiedParticleAdvection.EnhancedParticleConfig.particles_in_circle — Function
particles_in_circle(z; center, radius, n=100, pattern=:sunflower, seed=1234, precision=Float64, kwargs...)

Create n particles in a disk of radius around center = (x, y) at the coordinate z.

pattern places them:

  • :sunflower (default): a Fibonacci spiral, the most uniform;
  • :rings: concentric rings;
  • :random: uniformly at random, drawn from a generator seeded with seed, so the same call gives the same positions.

Example

config = particles_in_circle(-500.0; center=(250e3, 250e3), radius=50e3, n=200)

QGYBJplus.UnifiedParticleAdvection.EnhancedParticleConfig.particles_in_grid_3d — Function
particles_in_grid_3d(; x_max, y_max, z_max, nx, ny, nz, x_min=0, y_min=0, z_min=nothing, precision=Float64, kwargs...)

Create an nx by ny by nz regular particle grid. Horizontally the grid spans [x_min, x_max) and [y_min, y_max), as for a periodic domain; vertically its nz levels run from z_min to z_max, both included (the middle of the interval for nz = 1).

When z_min is supplied, z_min and z_max are coordinates. When it is omitted, z_max is interpreted as a positive depth below a lid at z = 0 and the vertical interval is [-z_max, 0].

config = particles_in_grid_3d(
    x_min=first(model.grid.x_faces), x_max=last(model.grid.x_faces),
    y_min=first(model.grid.y_faces), y_max=last(model.grid.y_faces),
    z_min=first(model.grid.z_faces), z_max=last(model.grid.z_faces),
    nx=10, ny=10, nz=10,
)

Interpolation

QGYBJplus.UnifiedParticleAdvection.InterpolationSchemes.InterpolationMethod — Type

Available interpolation methods. The errors are for smooth fields on a grid of spacing h.

  • TRILINEAR: linear in each direction (2-point stencil), O(h²), continuous.
  • TRICUBIC: Catmull-Rom cubic (4-point stencil), O(h³), continuously differentiable. The default.
  • QUINTIC: degree-5 Lagrange polynomial (6-point stencil), O(h⁶), continuous.
  • ADAPTIVE: deprecated, now the same as TRICUBIC.
source
QGYBJplus.UnifiedParticleAdvection.InterpolationSchemes.interpolate_velocity_advanced — Function
interpolate_velocity_advanced(x, y, z, u, v, w, grid_info, boundary_conditions, method)

Interpolate the cell-centred velocity components u, v, and w at (x, y, z) with method. w vanishes at the lid and the bottom, and u and v have zero vertical derivative there, as in interpolate_fields. The fields are read point by point, so they must be host arrays: for a model on a GPU, pass Array(model.fields.u) and so on.

source

Available methods are TRILINEAR, TRICUBIC (default), and QUINTIC; ADAPTIVE is deprecated and now uses TRICUBIC. See Particle interpolation. Particles move with the horizontal velocity and keep their depth; they are advected on the model's architecture, where the tracker keeps its copy of the velocity.

Use ParticleConfig3D or the distribution helpers to release particles at several depths, in volumes, layers, random points, or explicit positions.

Output

Particle trajectory helpers remain separate from Eulerian NetCDF snapshots:

QGYBJplus.ParticleIO.ParticleOutputManager — Type
ParticleOutputManager(output_dir; save_interval_iter=0,
                      save_interval_time=0,
                      output_mode=:trajectory,
                      file_prefix="particles",
                      overwrite=false)

Schedule particle NetCDF output under output_dir/particles, every save_interval_iter iterations or every save_interval_time in the model's time units (at its multiples from t = 0, like a TimeInterval): give one of them; the iteration interval wins when both are positive. output_mode may be:

  • :trajectory: one file, <prefix>_trajectory.nc, written when the run ends;
  • :streaming: one file, <prefix>_stream.nc, extended at every save, so a run that is killed keeps the trajectories saved so far;
  • :snapshots: one file per save, <prefix>_<iteration>.nc, with the iteration padded to 8 digits so that the names sort in time order.

Each record holds the particle positions and their velocities at the recorded time; times are Float64, and positions are stored in precision T. Existing files of the same mode and prefix raise an error unless overwrite=true, which removes them. Particle positions are not part of the model restart files, so a restored simulation starts new trajectories: write them to another directory or prefix, or pass overwrite=true.

Pass the manager as particle_output when constructing a QGYBJplus.Simulation. The simulation writes initial, scheduled, and final particle states and closes the manager when its run ends, so each manager serves one run: give a new simulation a new manager.

source

QGYBJplus.ParticleIO.write_particle_trajectories_by_zlevel — Function
write_particle_trajectories_by_zlevel(base_filename, tracker;
                                      z_tolerance=1e-6, metadata=Dict())

Write the tracker's in-memory trajectory history to one NetCDF file per initial z level, to analyse particles at different depths separately. Particles whose initial z differ by at most z_tolerance share a level. The files are named after the level, <base_filename>_z<z>.nc with the decimal point written p (for example particles_z-250p0.nc), and record it in their z_level attribute. Returns a Dict from each level to its file.

The tracker keeps a history only when its configuration sets save_interval (see ParticleConfig).

Example:

config = particles_in_layers(
    [-250.0, -500.0, -750.0];
    x_min=first(model.grid.x_faces), x_max=last(model.grid.x_faces),
    y_min=first(model.grid.y_faces), y_max=last(model.grid.y_faces),
    nx=4, ny=4, save_interval=3600.0,
)
initialize_particles!(simulation, config)
run!(simulation)

files = write_particle_trajectories_by_zlevel("particles", simulation.model.particles)
# particles_z-250p0.nc, particles_z-500p0.nc, particles_z-750p0.nc
