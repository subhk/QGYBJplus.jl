Core types

Ownership

QGYBJplus.RectilinearGrid — Type
RectilinearGrid([architecture=CPU()], [FT=Float64]; size, extent=nothing,
                x=nothing, y=nothing, z=nothing, centered=false)

Immutable owner of the model's global rectilinear geometry. Horizontal coordinates are periodic Fourier collocation nodes on half-open intervals; vertical coordinates are cell centers between z_faces.

Provide size=(nx, ny, nz) together with either extent=(Lx, Ly, Lz) or explicit bounds x=(x₁, x₂), y=(y₁, y₂), and z=(z₁, z₂). When only extent is supplied, the horizontal origin is zero (or centered when centered=true) and the vertical interval is (-Lz, 0). The kx and ky properties use FFTW's spectral ordering.

architecture selects where a model built on this grid stores and computes its fields: CPU() (default) or GPU(). The coordinate vectors held by the grid itself always live on the host. A GPU backend is stored as its arrays report it (see array_architecture).

FT is the floating-point type of the grid and of every array of a model built on it. Float32 halves the model's memory and is much faster on most GPUs; see the performance page for its accuracy.

grid = RectilinearGrid(GPU(); size=(128, 128, 64), extent=(1e5, 1e5, 4e3))
grid32 = RectilinearGrid(GPU(), Float32; size=(256, 256, 128), extent=(1e5, 1e5, 4e3))

QGYBJplus.ModelFields — Type
ModelFields{T, RT, CT}

Prognostic and diagnostic arrays owned by a QG-YBJ model. All fields use (z, x, y) dimension order. The prognostic fields q and B, together with the diagnostic fields psi, A, and C, are spectral and complex-valued; the velocity fields u, v, and w are real-valued.

RT and CT are the array types of the model's architecture: Array on the CPU, or the GPU package's device array (e.g. CuArray) on a GPU.

step! updates these arrays in place, so references to the container and to its individual arrays both stay live across steps.

QGYBJplus.ModelRuntime — Type
ModelRuntime

Ephemeral execution resources associated with a model: its architecture, kernel-facing geometry, transform plans, scratch workspace, operator coefficients, and dealiasing mask.

QGYBJplus.Simulation — Type
Simulation(model; Δt=1.0, stop_time=nothing, stop_iteration=nothing,
           output=false, diagnostics=false, particle_output=nothing,
           verbose=true)

Lifecycle owner for a model run. The simulation composes a model, clock, typed timestepper, stop criteria, scheduling/output configuration, and state.

  • Δt: the ETD-RK2 time step. The clock keeps time in Float64 as t₀ + nΔt, whatever the type of Δt.
  • stop_time or stop_iteration (not both): when run! stops; with neither, after 1000 iterations.
  • output: a NetCDFOutput, or false for none.
  • diagnostics: an EnergyDiagnosticsOutput, a schedule (an IterationInterval, TimeInterval, or integer number of iterations) for energy files in the diagnostic/ subdirectory of the output's path (or of output/), or false for none.
  • particle_output: a ParticleOutputManager for the particles installed on the model, or false/nothing. A manager serves one run.
  • verbose: log the progress every diagnostics_interval iterations (10 by default; see run!).

A simulation runs once: after run! it is Stopped, and a new simulation around the same model continues from its fields.

Numerical components

QGYBJplus.HorizontalHyperdiffusivity — Type
HorizontalHyperdiffusivity(; flow, wave)

Horizontal damping composed from explicit balanced-flow and wave components.

The no-argument constructor, also the model's default closure, keeps the fourth- and twelfth-order terms of nondimensional setups: coefficients (0.01, 10.0) for the flow and (0.0, 10.0) for the waves. With dimensional wavenumbers (kₕ ~ 10⁻⁴ m⁻¹) they damp nothing, so a dimensional run should give its own coefficients, for instance from compute_hyperdiff_coeff:

ν = compute_hyperdiff_coeff(dx=grid.dx, dy=grid.dy, dt=Δt, order=8)
closure = HorizontalHyperdiffusivity(flow=FlowHyperdiffusivity(coefficient=ν, order=8),
                                     wave=WaveHyperdiffusivity(coefficient=ν, order=8))

Initialization and scheduling

QGYBJplus.set! — Function
set!(owner; ψ, ζ, mean_flow, pv_method=:qg, waves, B, particles)

Set declarative initial conditions on a model or its simulation.

The mean flow is given by its streamfunction ψ (or psi, or mean_flow, which also takes a RandomStreamfunction) or by its relative vorticity ζ (or zeta), from which ψ follows by inverting ∇ₕ²ψ = ζ at each level. pv_method selects how the potential vorticity follows from ψ: :qg, :barotropic, or :none. B (or waves, which also takes a SurfaceWave) sets the wave envelope. ψ and ζ may be functions of (x, y, z); all three may be arrays on the model's grid, FieldArrays, or FieldFiles. particles takes a ParticleConfig or ParticleConfig3D (see initialize_particles!).

Every argument is checked, and every array and file read, before the model changes, so a rejected call leaves it as it was.

source
QGYBJplus.set_mean_flow! — Function
set_mean_flow!(owner; psi_func, pv_method=:qg, verbose=true)
set_mean_flow!(owner; method=:random, amplitude, spectral_slope=-3, seed=0, profile=nothing, pv_method=:qg)

Set the balanced streamfunction ψ of a model or its simulation, from a function psi_func(x, y, z) (method=:function, the default) or as a random flow (method=:random, see RandomStreamfunction: amplitude is the rms horizontal velocity). pv_method selects how the potential vorticity follows from ψ: :qg (with vortex stretching), :barotropic (relative vorticity only), or :none (q unchanged, for a FixedFlow model).

source
QGYBJplus.set_surface_waves! — Function
set_surface_waves!(owner; amplitude, surface_depth, profile=:gaussian, pv_method=:qg, verbose=true)

Set a horizontally uniform, surface-confined wave envelope B, as SurfaceWave does in set!: amplitude times exp(-d²/surface_depth²) (profile=:gaussian) or exp(-d/surface_depth) (:exponential), with d the depth of each cell's upper face below the top of the domain, its rigid lid (so the top cell has the full amplitude). The depth mean of B is then removed (see YBJ⁺ wave model).

source

set_exponential_surface_waves!(owner; amplitude, efold_depth, pv_method=:qg, verbose=true)

set_surface_waves! with the exponential profile amplitude * exp(-d/efold_depth).

source
QGYBJplus.set_wave_packet! — Function
set_wave_packet!(owner; amplitude, kx, ky, sigma_k, center=nothing, z_center=nothing, z_width=nothing, pv_method=:qg)

Set the wave envelope B to a Gaussian wave packet: a plane wave of wavenumber (2π kx/Lx, 2π ky/Ly) (kx and ky are integer mode indices) under a horizontal Gaussian envelope centred at center = (x, y), the middle of the domain by default. The spectral width sigma_k, in mode indices, sets the packet's width, about Lx / (2π sigma_k). Vertically the envelope is Gaussian, centred z_center below the top of the domain with width z_width (half and a quarter of the depth by default). amplitude is the packet's largest |B|, before the envelope is restricted to the modes a wave amplitude can produce. The packet involves no randomness.

source
QGYBJplus.SurfaceWave — Type
SurfaceWave(; amplitude, scale, profile=:gaussian)

Horizontally uniform, surface-confined wave initial condition for set!: amplitude times exp(-d²/scale²) (profile=:gaussian) or exp(-d/scale) (:exponential), with d the depth of each cell's upper face below the top of the domain, its rigid lid (so the top cell has the full amplitude). Its depth mean is removed when it is set, since the wave velocity has no barotropic part.

source
QGYBJplus.RandomStreamfunction — Type
RandomStreamfunction(; amplitude, spectral_slope=-3, seed=0, profile=nothing)

A random balanced flow for set!: a streamfunction whose horizontal velocity has root-mean-square amplitude over the domain (m/s in a dimensional setup). Every horizontal Fourier mode within the two-thirds dealiasing radius has a random phase and a variance proportional to |k|^spectral_slope, with |k| the mode index. The field is the same at every level, or proportional to profile(z) at the level z when a profile function is given. The same seed gives the same field on every architecture, up to rounding in a GPU's math library.

source
QGYBJplus.FieldArray — Type
FieldArray(values; space=:physical, layout=:zxy, x=nothing, y=nothing, z=nothing)

A three-dimensional field supplied directly to set!, on the model's grid or, when the coordinate vectors x, y, and z of its points are given (in the grid's coordinates, z positive upward), on any rectilinear grid, from which it is interpolated onto the model's. layout is the order of the array's dimensions, :zxy or :xyz. Its values must be finite.

source
QGYBJplus.FieldFile — Type
FieldFile(path, variable; space=:physical, layout=:xyz, group=nothing)

A three-dimensional field supplied to set!, read from a NetCDF file, or from a JLD2 file when path ends in .jld2. group names the NetCDF group, or the JLD2 group, NamedTuple, or Dict, that holds variable.

The dimensions of a NetCDF variable are put in order by their names when they name the axes (x, y, and z or depth, or common alternatives such as lon, lat, and lev); otherwise, and for JLD2 arrays, layout gives their order (:xyz or :zxy). Extra dimensions of length one, such as a single time, are dropped. Missing (fill) and non-finite values are errors.

When the same place holds coordinate vectors x, y, and z (or depth), a field on another grid is interpolated onto the model's. z is in the grid's coordinates, positive upward, and depth is measured down from the top of the grid, its lid; a z with no point below the lid, and some above it, is read as depth, as in earlier versions.

source
QGYBJplus.TimeInterval — Type
TimeInterval(interval)

Schedule output or diagnostics every interval of model time (seconds in a dimensional setup). The scheduled times are the multiples of interval from t = 0, so a restored run keeps the times of the original one; each is written at the first step that reaches it. The interval is kept in Float64, like the simulation clock.

source
QGYBJplus.IterationInterval — Type
IterationInterval(interval)

Schedule output or diagnostics every interval model iterations.

source
QGYBJplus.NetCDFOutput — Type
NetCDFOutput(; path="output", schedule=nothing, fields=(:ψ, :waves), velocities=false, overwrite=false)

Declarative NetCDF output settings: one state file stateNNNN.nc in path per write. schedule may be a TimeInterval or IterationInterval; with schedule=nothing only the initial and final states are written.

Every file holds the prognostic q and B needed for a restart (and ψ for a FixedFlow model). fields adds physical-space fields: :ψ (or :psi, :q, :flow) for the streamfunction, :waves (or :wave, :B, :A) for the wave amplitude A and velocity LA, and :velocities for u, v, and w, which velocities=true also adds.

A run never silently replaces state files already in path. A simulation restored with restore! continues the numbering after the files up to its restart iteration. Any other existing files raise an error unless overwrite=true, which removes them: all state files for a run that starts at iteration 0, and the files after the restart iteration for a restored run.

source
QGYBJplus.EnergyDiagnosticsOutput — Type
EnergyDiagnosticsOutput(; path="output/diagnostic", schedule, overwrite=false)

Configuration for simulation-owned energy time-series files. path is the diagnostic directory itself, and schedule may be time- or iteration-based. The files are rewritten as the run goes, at most every few seconds of wall time, and once more when it ends.

A restored simulation appends to the series already in path. Any other existing series raises an error unless overwrite=true, which replaces it (for a restored run, only the records after the restart time).

source
QGYBJplus.restore! — Function
restore!(model, path)
restore!(simulation, path)

Restore the prognostic q and B fields from a simulation state file and rebuild the model's diagnostic fields. The file must be for a domain of the same size and resolution; a different f or N² warns.

A FixedFlow model takes its prescribed streamfunction from the file; an evolving flow is inverted from the restored q.

Restoring a Simulation also sets its clock to the file's time and iteration, so output, diagnostics, and particles continue from there, and stop_time and stop_iteration keep counting from the original start.

source

Stratification

QGYBJplus.StratificationProfile — Type
StratificationProfile{T}

Abstract type for stratification profiles. Every profile but AnalyticalProfile is defined by depth below the surface: evaluate_N2(profile, z) takes the depth as -z, for a lid at z = 0, and a model whose grid has its top at z_top samples the profile at z - z_top, so that depths are always measured below its lid. An AnalyticalProfile is evaluated at the grid's own z.

source
QGYBJplus.ConstantN — Type
ConstantN{T}(N0) <: StratificationProfile{T}

Constant buoyancy frequency N0: N² = N0² at every depth.

source
QGYBJplus.SkewedGaussian — Type
SkewedGaussian{T}(N02, N12, sigma, z0, alpha) <: StratificationProfile{T}

The stratification of the original Fortran test cases: a pycnocline of peak N² N12 above the background N02, centred at the depth z0 below the surface, with width sigma and skewness alpha (see evaluate_N2).

source
QGYBJplus.TanhProfile — Type
TanhProfile{T}(N_upper, N_lower, z_pycno, width) <: StratificationProfile{T}

A pycnocline: N changes from N_upper near the surface to N_lower at depth across the depth z_pycno below the surface, over width, N(d) = N_upper + (N_lower - N_upper)(1 + tanh((d - z_pycno)/width))/2.

source
QGYBJplus.ExponentialProfile — Type
ExponentialProfile{T}(N_surface, scale_height, N_deep) <: StratificationProfile{T}

N decaying from N_surface at the surface toward N_deep over the depth scale scale_height, N(d) = N_deep + (N_surface - N_deep) exp(-d/scale_height).

source
QGYBJplus.PiecewiseProfile — Type
PiecewiseProfile(z_interfaces, N_values)

Piecewise constant stratification: N = N_values[i] for depths from z_interfaces[i] to z_interfaces[i + 1] (positive below the surface, strictly increasing), so there is one value fewer than interfaces. Depths above the first interface take the top layer's value, and depths below the last one the bottom layer's.

source
QGYBJplus.FileProfile — Type
FileProfile{T}(filename, z_data, N2_data) <: StratificationProfile{T}

Tabulated N² values N2_data at depths z_data (positive downward, strictly increasing, finite, and as many as the N² values), as returned by load_stratification_from_file. evaluate_N2 interpolates linearly in depth and holds the end values beyond the data.

source

AnalyticalProfile{T} <: StratificationProfile{T}

Analytical stratification profile from a user-provided function.

QGYBJplus.evaluate_N2 — Function
evaluate_N2(profile, z)

N² of profile at the height z relative to a lid at z = 0, that is at the depth -z; an AnalyticalProfile is evaluated at z itself. A model samples its profile at its own levels measured from its lid (see StratificationProfile).

source
evaluate_N2(profile::SkewedGaussian, z::Real)

Evaluate N² for skewed Gaussian profile, the stratification of the Fortran test cases, at the depth d = -z: N²(d) = N₁² exp(-(d-z₀)²/σ²) [1 + erf(α(d-z₀)/(σ√2))] + N₀²

This creates a realistic pycnocline with:

  • Enhanced stratification near z₀
  • Asymmetric shape controlled by α (via error function)
  • Background N₀² in deep ocean

QGYBJplus.compute_stratification_profile — Function
compute_stratification_profile(profile::StratificationProfile, grid::RectilinearGrid)

Compute the pointwise N² profile at the model's cell centers (grid.z), with depths measured below the top of the grid (see StratificationProfile).

Flux-form vertical operators use a separately sampled upper-face profile; see _compute_stratification_face_profile.

source
QGYBJplus.load_stratification_from_file — Function
load_stratification_from_file(filename::String; group=nothing)

Load a tabulated N² profile from a NetCDF file, or from a JLD2 file when filename ends in .jld2.

The file must hold a vertical coordinate named z or depth and N² named N2, N², or n2, as real arrays of equal length. depth is positive downward and z positive upward, both relative to the surface; a z without negative values is read as depth, as in earlier versions. group names the NetCDF group, or the JLD2 group, NamedTuple, or Dict, that holds the arrays, e.g. group="ocean/cast12". JLD2 arrays may be ranges.

The data need not be sorted or lie on the model's levels: the model interpolates the profile linearly in depth below its lid to its own cell centers and faces, holds the end values beyond the data, and warns when that leaves more than one grid spacing uncovered at the top or bottom of the domain.

source
QGYBJplus.validate_stratification — Function
validate_stratification(N2_profile::Vector) -> (errors, warnings)

Check a sampled N² profile, returning lists of messages. Errors: an empty profile, non-finite values, and N² ≤ 0 (unstable or neutral). Warnings: N² above 100 or below 1e-6, which in s⁻² usually signals a units mistake (though abyssal N² can fall below 1e-6), and jumps between neighbouring values much larger than the profile's average change.
